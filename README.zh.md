# pi-rollback

**Pi 扩展** — 通过文件系统快照,让文件状态与会话树导航保持同步。

适用于**任何**项目目录。无需 Git。

## 为什么需要它

Pi 的 `/tree` 命令可以浏览对话历史,但**文件始终停留在当前状态**。如果你发现走错了方向,可以回溯对话,但代码改动依然存在。

`pi-rollback` 在每次用户消息处理**之前**和**每个回合结束时**自动创建**文件快照**。当你用 `/tree` 跳到某个节点时,它会(在确认后)把文件恢复到该节点对应的快照 —— **对话位置和文件状态保持同步**。

## 工作原理

1. **消息前快照(pre)** — 在每次用户消息发送给 LLM **之前**(`before_agent_start` 事件),扫描所有项目文件,将文件内容存入内容寻址的对象存储中(`<state-root>/<project-key>/objects/<sha256>`)。未变更的文件自动去重。这捕捉的是 LLM 做任何改动**之前**的文件系统状态。

2. **回合后快照(post)** — 每个回合(assistant 消息 + 工具执行)结束时(`turn_end` 事件)记录文件状态,并锚定到该回合的 assistant 消息;文件无变化时跳过,不会无谓膨胀。

3. **`/tree` 文件恢复** — 导航时按你**实际选中的节点**决定目标状态:
   - 选中 **user 消息**(Pi 会把它从对话移回编辑器)= "撤销这条" → 恢复到该消息处理**前**的状态;
   - 选中**其他节点**(assistant 回复、工具结果等)= "从这里继续" → 恢复到该节点**处**的状态。

   如果磁盘与该状态不一致,会询问确认,然后恢复文件(并删除不属于目标状态的文件)。

4. **条目绑定** — 在 `turn_end` 时,最新检查点与最新用户消息条目进行文本匹配并持久化绑定,使后续树跳转能精确地将节点映射到检查点。

## 安装

```bash
# 从本地目录加载
pi -e ./path/to/pi-rollback/index.ts

# 或复制到项目目录
cp -r pi-rollback .pi/extensions/
pi
/reload
```

## 使用方法

像往常一样用 `/tree` 导航会话树:

- 选中 **user 消息** = 撤销这条、重新编辑:文件恢复到该消息处理前(确认框标注 "File state **before** turn #N")。
- 选中 **assistant 等节点** = 从这里继续:文件恢复到该节点处的状态(确认框标注 "File state **after** turn #N")。
- 文件状态与磁盘不一致时,会弹出确认框,列出将恢复和删除的文件。确认 → 文件回滚到目标状态;拒绝 → 对话移动,文件保持不变。
- 纯对话跳转(无文件差异)**不会**打扰你。
- 在 Pi 之外被修改的文件(编辑器、bash)会被恢复**直接覆盖** —— 检查点是权威状态。

## 忽略文件:`.rollbackignore`

在项目根目录创建 `.rollbackignore` 文件,以排除某些文件/文件夹不被纳入检查点。
语法与 `.gitignore` 类似:

```gitignore
# 忽略大型资源目录
assets/videos/
*.zip

# 忽略特定文件
secrets.json
.env

# 锚定到项目根目录(以 / 开头)
/build/
```

### 忽略优先级

1. **内置默认规则** — 始终生效(`.git/`、`node_modules/`、`.rollback/` 等)
2. **`.rollbackignore`** — 项目根目录,用户的忽略文件

> 注意:不支持取反模式(`!pattern`)。

## 存储结构

状态存储在**全局**目录中(每个项目一个子目录),项目目录保持干净:

```
<state-root>/                        # $PI_ROLLBACK_STATE_DIR 或 ~/.pi/agent/state/rollback
  <project-key>/                     # 项目根路径的 sha256(前 12 位)
    sessions/<session-id>.jsonl      # 每个会话独立的检查点记录
    objects/<sha256>                 # 按哈希存储的文件内容(去重)
<project-root>/
  .rollbackignore                    # 项目级忽略规则(保留在项目内)
```

- `<project-key>` 由项目根路径哈希生成,不同项目互不冲突,且可以按项目单独清理(删除 `<state-root>/` 下对应子目录)。
- 可通过环境变量 `PI_ROLLBACK_STATE_DIR` 覆盖状态根目录。
- 全局布局之前的旧检查点(位于 `<project>/.rollback/`)**不会**自动迁移——直接删除该目录即可。
- 每个会话(session)拥有独立的检查点文件(以会话文件名命名),因此 fork 出来的会话不会产生冲突。

### 默认忽略的内容

- `.rollbackignore` 自身
- `.rollback/`、`.git/`、`node_modules/`、`.pi/`
- 构建输出:`dist/`、`build/`、`.next/`、`.turbo/`、`coverage/`、`.cache/`、`__pycache__/`
- 编辑器文件:`.DS_Store`、`*.swp`、`*.swo`
- 日志:`*.log`、`*.pyc`
- 锁定文件:`package-lock.json`、`yarn.lock`、`pnpm-lock.yaml`、`bun.lock`、`bun.lockb`

## 恢复策略

`/tree` 导航时,pi-rollback 先通过 `session_before_tree` 拿到你**实际选中的节点**(Pi 在选中 user 消息时会把 leaf 移到它的父节点、文本放回编辑器,所以这个信息只能从该事件获得),再解析目标快照:

1. **选中 user 消息** → 目标 = 该消息的处理前快照:
   - `userEntryId` 精确匹配(在 `turn_end` 回填);
   - 文本配对兜底:未绑定的检查点(从旧到新)依序绑定第一个文本匹配且未使用的用户消息(重复提示词按顺序绑定;带图片时 Pi 追加的降采样 hints 也能匹配);
   - 仍无结果(如流中排队的 steer 消息没有自己的快照)→ 用到其父节点处最近的锚定快照;
   - 第一条消息 → 初始状态。

2. **选中其他节点** → 目标 = 该节点处的状态:
   - 该节点自己的 post 快照(回合结束时记录,锚定 assistant 消息);
   - 没有 post(该回合未改动文件)→ branch 中位置 ≤ 该节点的最近锚定快照(此时内容相同,结果一致)。

锚点不在当前分支(已被剪枝)的记录会被忽略;无法解析时跳过恢复,文件保持不变。

## 设计细节

- **内容寻址存储** — 文件按 SHA256 哈希值只存储一次。同一文件内容在多个检查点中出现时,磁盘上仅保留一份。
- **完整的文件映射** — 每个检查点记录完整的文件状态:每个文件路径 → 其内容哈希值。这使得恢复操作为 O(1):只需从映射中复制回所有文件即可。
- **干净恢复** — 恢复检查点中的文件,同时删除工作目录中不属于该检查点的文件。
- **工具无关** — 不监听特定的工具名称。直接扫描文件系统,因此能捕获来自 `write`、`edit`、`bash` 或任何扩展工具的修改。
- **恢复前询问** — `/tree` 跳转从不静默修改文件,文件变更总是先确认。

## 自检

核心逻辑(节点映射、差异计算、文件恢复)的纯 assert 自检,无需测试框架:

```bash
node selfcheck.ts
```

## 提示

- 跳回后,继续从该节点工作——新的用户消息会在发送给 LLM 之前自动创建新的检查点。
- 要清理某个项目的检查点,删除状态根目录下对应的子目录(`~/.pi/agent/state/rollback/<project-key>/`)。
- `.rollbackignore` 文件本身会自动排除在检查点之外。
